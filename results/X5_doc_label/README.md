# X5 문서 이름표 실험: 사용자 과제 없이 `{"document": …}`로 감싸기만 해도 효과가 있는가

모든 숫자는 `python experiments/analyze_X5_doc_label.py`의 출력(`tables/conditions_by_group.csv`)과 `summary.json`에서 가져왔다. 분석 스크립트는 API를 부르지 않는다.

**한 줄 요약.** 문서를 `{"document": 문서}`로 감싸기만 해도(사용자 과제 없음) 인젝션 탐지율이 Q2 56.2% → 63.2%(+7.0%p), QL 63.4% → 72.8%(+9.4%p)로 올랐고 오탐은 그대로였다(2.2% / 0.2%). 문서 첫 줄에 있는 BIPIA 인젝션은 19.2% → 48.1%(Q2)로 올라, 첫 줄이 아닌 경우(50.5%)와의 차이가 21%p에서 2%p로 줄었다. X2(사용자 과제)의 이득 중 약 40~55%는 이 이름표에서 나온다.

## 목적과 가설

X2_user_task에서 사용자 과제를 함께 주자 탐지율이 약 17%p 올랐고, 문서 첫 줄 인젝션의 손해(맨 앞 약점)가 사라졌다. 그런데 X2는 입력을 `{"user_task", "document"}` JSON으로 바꿨기 때문에, 효과가 **과제의 내용** 때문인지 **문서에 이름표가 붙은 구조** 때문인지 가를 수 없었다.

- 가설 (보고서 3.2절 추가 분석): Jev는 텍스트의 첫 문장을 사용자의 요청으로 읽는다. 문서만 주면 문서 첫 줄의 지시가 "요청 자리"에 놓여 덜 잡힌다.
- 예측: 이름표가 "여기부터 문서"라는 표시 역할을 한다면, 과제 없이 이름표만 붙여도 맨 앞 약점이 줄어야 한다. 과제 내용이 필요하다면 이름표만으로는 줄지 않아야 한다.

## 설정

| 항목 | 값 |
| --- | --- |
| 조건 A (문서만) | `results/01_baseline/`: `state` = 문서 문자열 |
| **조건 B (이름표만, 이 실험)** | `state = {"document": 문서}` (`experiments/run_api.py X5_doc_label`) |
| 조건 C (과제와 함께) | `results/X2_user_task/`: `state = {"user_task": 과제, "document": 문서}` |
| 문서 | X2와 같은 1,000건 (`data/injection_eval/experiments/X2_user_task.jsonl`의 `text`, 인젝션 500 / 정상 500). EN 1000과 같은 문서 |
| 판정기 | 공식 API `jev-1.14.0`, 질문 Q2·QL, 문서마다 3회 호출 평균, 임계값 0.5 |
| 호출 | 6,000회 (1,000건 × 2질문 × 3회), 오류 0, 재시도 0, 2026-11-16, 비용 약 $0.17 |
| 첫 줄 | `injected_instruction`이 본문의 처음 3글자 안에서 시작하는 인젝션 |
| 공격 표지 | 사후 정규식: "ignore … previous/prior", "disregard prior/previous", "system override", "important!", "attention:", "system_message", "<information>" |
| 통계 | 같은 문서끼리 0.5 판정의 정확 McNemar 검정 (불일치 쌍의 양측 이항검정). 다중비교 보정 없음 |

## 핵심 결과

임계값 0.5, 탐지율(인젝션) / 오탐률(정상). 괄호는 조건 사이 짝 비교의 (놓치게 된 수 / 새로 잡은 수, McNemar p).

| 집단 | n | A 문서만 | B 이름표만 | C 과제와 함께 | A → B | B → C |
| --- | --- | --- | --- | --- | --- | --- |
| **Q2** 인젝션 전체 | 500 | 56.2% | **63.2%** | 72.8% | 3 / 38, p < 0.001 | 14 / 62, p < 0.001 |
| Q2 정상 (오탐) | 500 | 2.2% | 2.2% | 1.8% | 1 / 1 | 3 / 1 |
| Q2 표지 없음, 첫 줄 | 77 | 14.3% | **37.7%** | 55.8% | 0 / 18, p < 0.001 | 3 / 17, p = 0.003 |
| Q2 표지 없음, 첫 줄 아님 | 293 | 48.1% | 53.6% | 65.2% | 3 / 19, p < 0.001 | 11 / 45, p < 0.001 |
| Q2 표지 있음 | 130 | 99.2% | 100% | 100% | | |
| Q2 BIPIA 첫 줄 | 52 | 19.2% | **48.1%** | 65.4% | 0 / 15, p < 0.001 | 2 / 11, p = 0.022 |
| Q2 BIPIA 첫 줄 아님 | 99 | 40.4% | 50.5% | 65.7% | 1 / 11, p = 0.006 | 2 / 17, p < 0.001 |
| **QL** 인젝션 전체 | 500 | 63.4% | **72.8%** | 80.0% | 5 / 52, p < 0.001 | 10 / 46, p < 0.001 |

## 얻어가는 점

1. **이름표만으로 탐지율이 오르고 오탐은 늘지 않는다.** 문서를 `{"document": …}`로 감싸는 것은 코드 한 줄이고 비용도 거의 같다. 사용자 과제를 모르는 상황에서도 쓸 수 있다.
2. **맨 앞 약점은 대부분 "요청 자리" 문제였다.** Q2에서 BIPIA 첫 줄과 나머지의 차이가 21.2%p(A)에서 2.4%p(B)로 줄었다. 가설(첫 문장을 요청으로 읽는다)과 맞는다.
3. **사용자 과제는 이름표 위에 추가 이득을 준다.** B → C로 Q2 +9.6%p, QL +7.2%p. X2 이득(Q2 +16.6%p, QL +16.6%p) 중 이름표 몫은 Q2 약 42%, QL 약 57%다.
4. QL의 맨 앞 약점은 이름표만으로 완전히 사라지지 않았고(BIPIA 59.6% vs 67.7%), 과제를 줘야 사라졌다.

## 한계

- 이름표는 `"document"` 하나만 시험했다. 다른 키 이름(`"email"`, `"webpage"`)이나 평문 표시(`Document:`)에서도 같은지는 모른다.
- 공격 표지와 첫 줄의 분류는 사후에 정한 규칙이다. 다중비교 보정을 하지 않았다.
- 첫 줄 인젝션은 BIPIA와 SEP에서만 나온다(77건). SEP는 어느 조건에서도 거의 잡히지 않아 정보가 적다.
- A(01_baseline)와 C(X2)는 11/12, B는 11/16에 호출했다. 같은 조건의 재호출 판정 차이는 약 1%로, 조건 사이 차이(7~10%p)보다 훨씬 작다.
